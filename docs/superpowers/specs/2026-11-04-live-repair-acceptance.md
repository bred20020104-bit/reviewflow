# 真实自动修复与隔离验收设计

## 用户目标与授权

2026-11-04，用户明确要求让 ReviewFlow 对含人工埋设bug的 feat/test 仓库按正常流程测试并直接修改，不接受开发助手手修代替产品。随后明确允许本机安装/配置Docker兼容环境与准备测试镜像。

本设计实现：产品真实审查→独立复核→模型Patch→隔离候选修改→全部目标测试→真实再审查→通过后由产品写回测试工作区。用户已批准这一完整流程方向；不重复询问是否开发。新的付费模型请求总额必须在预览后另行授权，上一轮13/16调用已关闭。

## 输入边界

- 首次验收沿用既有6个被测源文件：mcm_analysis/{events,protocol,relay,task,throttle,transport}.py。它们的两批真实模型审查可以重新执行；不向模型提供开发助手知道的bug答案，也不硬编码修复结果。
- “全部测试”指Git HEAD中可由pytest发现的全部仓库测试，不仅原6文件对应的测试。源码语义审查范围仍显式展示，不将6文件验收说成整个仓库所有逻辑已审查。
- 必须为有效Git HEAD；批准绑定root、分支、HEAD、所选源码hash、完整测试导出hash、模型配置、角色资源hash、测试镜像、预算、输出和写回策略。
- 原工作区已有dirty/index/untracked内容保留。若待修改文件本身与HEAD不同，则阻止写回，而非覆盖。工作期间分支/HEAD/index或受保护工作区状态发生变化则停止。
- 报告目录必须是目标之外全新目录；产品安装与配置可信，目标代码/文档/模型输出不可信。

## 现有基础的限制

- 已有propose_patch只接可信离线后端，输出完整文件。2048输出tokens不适合重写较长源文件。
- 现有Workspace.create只接完整可纳入的普通非可执行文本Git树；真实目标有脚本、配置模板和过滤条目，不应关闭原门禁来硬塞这个仓库。
- 现有DockerRunner仅支持repo@sha256镜像和固定根tests/目录；真实目标有多层测试目录，本地新构建镜像只有不可变image ID。
- 现有ValidationAuthority/Publisher用于更严格的发布资格。本轮不伪造其receipt，不使用execution="real"假标签绕过门禁，不产生commit_ready权限。

## 产品实现决策

### 1. 新的显式CLI控制器

增加 `review repair-run --development --config ... -d ... --include ... --image sha256:... --output ... [--approve DIGEST]`。

未批准只生成预览，无模型请求、worktree创建、目标测试或写回。批准的是有界自动修复策略：可在隔离候选中应用合法模型补丁；只有最终测试与再审查都达到要求，才能写回原有选定源码。仍不授权commit/push或修改测试/配置/依赖。

请求上限作为控制器的跨阶段总预算（最多48），每个现有DevelopmentTransport阶段保持最多8次、64KiB正文、2048输出tokens、60秒、零自动重试。传输/用量未知后全局停止，不创建新transport继续消费未知结果。所有实际adapter尝试都进入统一账本。

### 2. 安全的候选worktree和独立测试导出

增加专用候选工作区组件，不放宽旧Workspace的完整树要求或发布服务。

- 通过安全Git调用 `worktree add --detach --no-checkout` 创建外部全新隔离目录，无checkout filters/hooks，不切换原feat/test。
- 从固定HEAD手动物化有界普通文件；拒绝symlink/submodule、非法路径、超量、二进制或无法安全支持的树。脚本只作为文件物化，宿主不执行。
- 明确区分模型上传范围与测试导出范围：模型只接审批选定源码及必要的产品finding；测试容器需要HEAD内测试、源码、脚本和模板。实际凭据路径禁止，`.env.example`这类已提交模板可在本地隔离测试导出中显式列出，但不得作为模型上下文上传。完整导出清单/hash进入审批。
- Colima已配置无宿主共享；使用Docker托管临时volume和受控copy传输导出，不启用宿主共享。目标容器只以只读volume挂载复制出的导出文件，不挂Git元数据、原仓库、模型配置、凭据或Docker socket。全导出最多200文件、8MiB，单文件256KiB。旧bind runner行为保持兼容，新入口显式选择volume transport。
- 记录基线、每个候选的完整字节摘要、应用与恢复记录；未知用户修改阻止自动恢复。原目标到最终写回之前保持不变。

### 3. 真实Patch使用小范围精确编辑

新增独立结构化 EditProposal：快照、finding ID、若干{path,before_sha256,old_text,new_text}。old_text必须非空且在对应当前文件中唯一匹配，多个编辑不可重叠，必须有实际变化；禁止新增/删除/重命名文件。

产品在内存把编辑转换为既有PatchProposal完整替换，再调用既有validate_patch守卫：仅已有证据引用且在审批范围的普通.py，不改测试/config/依赖/构建/迁移。用户目标的正确代码不能由开发助手代写。

Patch系统配置增加按当前schema选择完整替换（离线兼容）或精确编辑（新真实入口）的明确说明。通过现有ResponsesAdapter/DevelopmentTransport发送，使用验证过的CodePacket文件内容，不绕过证据和正文校验。

### 4. 候选驱动和再验证

- 首先对原选定范围分批运行真实多Agent审查。全部所选路径需完整供给且两类Reviewer均完成；任何未复核候选或实质错误阻止后续自动应用。
- 仅选择产品自己提出且Verifier accepted、修复范围可支持的候选。保留条件/不确定性，不能为了全绿压低结论。
- 多个修改必须绑定当前候选快照。历史finding不得直接拿旧hash套用：若原证据文本仍唯一存在，可由产品重定位后交独立Verifier在当前上下文重新核验；否则必须重新审查受影响范围或停止并报告，不编造证据。
- 每个选中候选最多两次Patch尝试；失效/不合法输出不默默无限重试。全局请求预算独立限制所有尝试。
- 原HEAD先运行全量pytest基线；已有埋设bug导致基线失败允许继续修复，不能冒充基线通过。环境阻塞/超时/收集错误必须区分，不能绕过。
- 最终组合候选必须通过全量pytest；再对同一候选快照和所选源码范围做新的真实多Agent审查，完整覆盖、无工作流错误、无accepted/unresolved残留或未经复核候选，才可写回。
- 如果预算不足、测试失败、再审查仍有问题或修复范围不支持，保留候选和报告，原工作区不写回。不承诺所有埋设bug一定能修好。
- 不改目标测试；若已有测试不能复现某项bug，报告只能声称回归测试通过＋静态再审查，不虚构专用复现。

### 5. 真实隔离测试

- 安装Docker兼容运行时已获许可；环境准备并行进行，不自动继承为模型调用授权。
- DockerRunner新增严格的本地 `sha256:<64hex>` immutable ID支持，保留原repo@sha256支持；拒绝可变tag。
- 新增固定的仓库递归pytest suite；保留旧regression/reproducer语义。只运行产品固定Python/pytest包装命令，不运行目标提供的shell命令、构建脚本或依赖安装脚本。
- 镜像由可信独立Dockerfile构建，使用审核的显式依赖集合和固定基础镜像digest；镜像构建不含目标源码或私有配置，运行时禁网、只读、非root、去capabilities、CPU/内存/PID/时间限制、禁插件自动加载。
- 记录真实退出码、状态和镜像ID。安全报告不得复制任意目标日志/秘密。无Docker或测试环境不支持时blocked，不退回宿主运行。

### 6. 最终写回

仅接收本进程中来自实际runner及最终真实再审查的校验结果，绑定最终候选digest。不得从磁盘JSON恢复验证权限。

再次检查原分支/HEAD/index状态、所选源文件原始字节。只将已批准且经过验证的变更.py写回原工作区；使用no-follow、预期字节检查、逐文件原子替换。写入失败只恢复本操作仍拥有的内容；发现用户并发修改时停止并报告，不能覆盖或reset/stash。

不修改索引、不提交、不推送、不合并。输出最终diff、已修改文件、前后hash、测试与再审查证据、未解决事项及实际费用状态。

## Builder check 后明确的实现边界

以下均为实现选择，不是用户新的授权：

1. 审查、Patch和测试统一读取HEAD派生的候选；dirty工作区字节只用于冲突保护，不混入模型输入。
2. 受保护状态精确定义为原branch/HEAD/index清单hash、选定源码原始字节/父目录身份；不读取或声称监控全部无关untracked文件字节。
3. 自动写回要求运行期间用户不并发编辑选定源码。产品会检测已观察到的冲突并停止；no-follow及原子replace不等于对任意外部编辑器提供跨进程事务隔离，不作此承诺。
4. 仓库测试固定pytest发现根为/workspace，忽略目标pytest配置中的addopts/testpaths覆盖，允许正常测试conftest但只在容器内。固定wrapper检查collected/run/skipped和阶段错误：零实际执行或全skip不算通过；collection/setup/teardown/internal错误归blocked，普通call失败归failed。初版不保留目标原始日志和单测细节；退出状态可证明的范围与未保留统计必须写清，不能报告虚构测试数量。
5. 48是设计上限，不是已获付费授权。批准前产品开发和本地合成测试继续，真实模型测试仍待单独有界审批。

## 验收与交付

- 产品单元/集成测试先RED后GREEN，覆盖精确编辑边界、旧证据拒绝、审批变更、全局预算、未知usage停止、失败不写回、用户工作保护、成功写回和无发布权限。
- 本地合成Responses与实际CLI验证全流程接线，不把合成结果冒充用户仓库验收。
- Docker环境与固定runner真实验证，不仅mock。
- 用户仓库真实模型验收需新额度授权；报告提供可复制绝对路径。没有通过就明确记录failed/blocked/unresolved，不声称修复完成。
- 保留所有候选和日志；不自动清理用户可能查看的worktree。

# Responses 真实只读审查：有界开发模式

日期：2026-11-03。依据用户要求推进真实接入，以及本轮明确选择“允许有界开发测试”。

## 本轮目标

将已经单次验证过的第三方 Responses 接口接入 `review --review` 与现有交互式 LangGraph。默认盘点、模拟会话、正式费用门禁保持不变。本轮不实现前端、修复、commit/push、执行目标测试或真实会话恢复。

## 授权与模式

- 开发模式必须显式提供 `--development`、可信工具配置 `--config` 和目标 `-d`。没有此开关的真实入口继续失败闭合；不能宣称正式计费模式已验收。
- HTTP 或未知单价仅限这个独立开发模式。展示明文传输和金额未知警告；不能用虚构价格、零价格或字节假充 token 绕过 GuardedTransport。
- 固定上限：8 次网络请求、每次最终 HTTP JSON 正文 65,536 字节、请求输出上限 2,048 tokens、每次调用总期限 60 秒、0 自动重试、0 重定向。未知/非法 usage、超限、网络错误或不完整回复后阻止后续请求。
- 默认只有预览，不联网。预览摘要绑定模式、完整模型元数据（无 Key）、目标/root/source/snapshot、选定路径/hash、运行限额、适配器/提示词版本及输出目录。用户通过 `--approve <digest>` 批准一次有界运行。
- 后续每次请求仍经过 WorkflowGateway 的证据核验，运行内策略只能为绑定快照、路径、配置和限额内的请求签发一次性子授权；不能直接复用 demo 的无条件自动批准函数。
- `--include` 可重复，精确限制源码范围；默认所有纳入文件，但必须先预览。其他文件明确标为未选择/未审查，不能伪造全仓库覆盖。
- 报告输出目录必须全新、位于目标之外，不覆盖已有目录或文件。保存报告不包含 Key、原始请求或原始服务端错误；模型自由文本仍按敏感报告处理。

## 适配器

使用 Python 标准库实现窄 Responses HTTP 协议，不引入无必要 SDK、重试、代理环境或动态插件。请求仅有 instructions/input/text.format/model/store=false/stream=false/max_output_tokens，不启用远端工具或会话状态。Schema 做确定性 strict 格式转换（所有对象属性 required、删除 default），本地原始 Pydantic 模型仍是最终验证边界。

网络工作在可信 Python `-I -m` 子进程中，凭据经 stdin 内存管道传入，不在命令行/环境/日志中。父进程以 60 秒总超时终止并等待子进程；子进程限定响应体大小，不打印原始服务端正文。目标 Python 从不被导入。

开发配置读取原有五字段私有文件，使用独立配置类型支持明确 HTTP 例外；不放宽普通 ModelConfig 的 HTTPS 校验。凭据文件保护和相对配置目录解析复用现有实现。

## 工作流和报告

复用交互工作流的 Planner → 两个 Reviewer → 分组建议 → Verifier → 报告，以及原有单 Agent/无 Verifier 比较模式。工作流最多 8 次模型尝试，传输最多 8 次真实请求。

真实运行事实由可信控制器附加，不由模型填写。报告标记 `execution=live_development`，区分工作流尝试、网络请求、provider-reported token、未知美元费用、覆盖和失败原因；不沿用“模拟/网络0”文案。只有经过有效 Reviewer 结果验证的任务才计入语义审查；目标测试永远 false。

保留 complete/partial/failed，预算耗尽/验证失败必须保留部分报告并返回非零。原始模拟报告/会话协议继续兼容，不把新真实报告塞进模拟 SessionDocument。

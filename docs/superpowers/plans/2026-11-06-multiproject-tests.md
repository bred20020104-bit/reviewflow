# 多子项目测试兼容修复

目标：修复真实目标暴露的测试导入布局缺陷，提供不调用模型的真实测试入口；不修改目标源码/测试，不跳过失败测试，不放宽Docker隔离，不自动付费重跑。

## 决定

- 根据已校验的完整HEAD文件清单发现默认pytest文件名。tests/test目录的直接父级作为测试项目；不在这些目录中的测试按所在目录分组。所有发现的测试文件恰好分配一次，不读取或执行项目配置生成命令。
- 每组使用独立Python进程，在对应项目目录运行；导入路径依次包含项目目录、仓库根目录。组间不共享sys.modules，避免同名模块误导入。仍共享同一个只读导出和禁网容器。
- 每组传入明确测试文件集合；不因某组失败省略后面的组。普通断言失败允许进入现有修复流程；收集/setup/teardown/内部/参数错误均阻断。全部组未执行任何测试则阻断。
- 所有子进程受外层同一个容器期限与资源上限约束。不捕获/保存原始日志，使用固定退出码提供安全诊断分类。所有权、候选哈希、镜像和测试布局进入审批指纹。
- 添加 `repair-run --tests-only`：仍预览/批准、创建隔离候选、执行基线，但保证不进入模型或写回阶段；用于真实仓库测试适配验证。该模式绑定审批，不能使用测试审批启动模型修复。

## 步骤

1. 写真实子进程回归：嵌套裸import、同名模块隔离、根与包导入、失败优先级、全跳过、配置不能隐藏测试。观察失败。
2. 实现静态测试分组和容器内分组调度，固定安全诊断。组件测试转绿。
3. tests-only CLI与控制器门禁，变更审批无效和零模型/零写回测试先失败再通过。
4. 完整pytest和Ruff；实际安装CLI＋真实Docker对合成布局及原目标HEAD执行tests-only。目标业务断言失败仍如实报告，不手工修目标。
5. 独立审查本次改动，更新文档和中文报告。保留所有证据、候选与工作区，不commit/push。

完整版本边界：这里完成的是修复上述阻断并可实际运行的CLI后端，不包含尚未授权的真实模型修复验收、前端、Git发布或无限模型预算。
